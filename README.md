# Data Center Site Selection Engine

An end-to-end geospatial platform for siting **100+ MW hyperscale data centers**, built on a strict evidence discipline: every value in the decision layer is traceable to a named source, and **what is not known is shown as UNKNOWN — never invented**.

Two tiers run on the same map:

1. **Regional screening** — 10 km² fishnet cells scored on power, water, risk, and climate factors, clustered into Prime Development Zones (HIFLD / USGS / FEMA / NOAA live data). Ranking is **lexicographic on evidence** (Release 9): cells compare on `evidence_tier` first and score second, so a parcel-tier site out-ranks a screening-tier one whatever the two scores are. Within the parcel tier the composite is the screening score × `evidence_coverage` — the share of that region's parcel gates the current diligence can decide (Loudoun 0.995, Prince William 0.942, Licking 0.900, Franklin 0.777, Taylor 0.759) — so a partially diligenced site cannot match a fully diligenced one. Both fields are stored per cell, so the dashboard's live slider re-weighting re-applies the factor instead of silently un-doing it.

A screening-tier region keeps its composite **unscaled**. Scaling it by a coverage of 0 was not a penalty but an annihilator: Morrow County, OR lost all 330 observed screening composites to a single 0.00, discarding the best climate score of the four regions and flattening the region's internal ranking. `evidence_tier` is stored rather than read off `evidence_coverage > 0`, because a region with no parcels and a region whose parcel gates all came back UNKNOWN are different facts. Absent diligence is not a measurement of zero. The risked figure is **generated by the database** from `composite_score_unrisked`, the screening model's own output, so the worker never writes a product and cannot overwrite a measurement with one (see `docs/unrisked-composite-spec.md`).
2. **Parcel qualification** (parcel pilots: Loudoun and Prince William VA, Franklin and Licking OH, Taylor TX — next tiers scoped to the PJM footprint per [`docs/pjm-sourcing-decision.md`](./docs/pjm-sourcing-decision.md)) — cadastral parcels ≥20 acres run through **hard gates** (zoning use, floodway, wetlands, acreage, slope, protected land, road access, power capacity evidence, water availability) that return `PASS / CONDITIONAL / FAIL / UNKNOWN` with the rule, the affected-area percentage, and the source lineage behind every verdict. Power diligence (Release 2) records the serving utility, PJM Board-approved transmission upgrades with their energization dates, and the dated documents behind every capacity figure — and **removed the fabricated area-derived MW estimates**: no parcel displays a feasible MW number without a dated source that supports it. Water availability (Release 3) is judged from Loudoun Water's own published service-area boundary — including the utility's explicit NOT-Served polygon — with incorporated towns held UNKNOWN because their municipal providers are outside that layer.

## The Decision Model

**Four criterion kinds** govern a parcel:

| Kind | Examples | Output |
| :--- | :--- | :--- |
| Hard gate | zoning DC-use, floodway, wetlands, contiguous acreage, slope, protected land, road access, power capacity evidence | `PASS` / `CONDITIONAL` / `FAIL` / `UNKNOWN` |
| Scored factor | transmission/substation/road distances | metric values (never gates) |
| Verification-required | slope, protected land, road access, wetlands, power capacity, water availability | `UNKNOWN` until the evidence layer lands — no favorable default |
| Informational | ordinance vintage, assembly potential, utility documents | context metrics and dated sources |

**Four states.** A parcel's overall status is `FAIL` if any gate fails, `UNKNOWN` if any gate is unknown, `CONDITIONAL` if any is conditional, `PASS` only when every gate passes. Two gates can be decided by **dated parcel-specific records in the public county file** rather than by a rule about the district: power capacity since Release 2.1, and zoning since Release 14. The zoning case arrived because the law moved — Loudoun's ZOAM-2024-0001 (adopted 2025-03-18) ended by-right data-centre development in the IP, GI and MR-HI districts, so every Loudoun parcel now needs a Special Exception *unless the Board has already granted one*. A parcel-specific approval outranks its district: a classification is a rule about a category the land belongs to, an approved ZMAP, SPEX or ZCPA is the governing body permitting this use on this land, by name and on a date. Without that precedence the engine told seven parcels they required a Special Exception one of them already held in these very records. With it, a fully-`PASS` parcel exists again — a 129-acre Stonewall Secure Business Park parcel, passing zoning now because the Board approved data centres on it by name in 2011 (ZMAP-2008-0017) rather than because its district happened to be by-right. The stronger claim survived the ordinance that removed the weaker one.

**Evidence classes** tag every metric row: `observed` (fetched as-is), `derived` (computed from observations — overlaps, slopes, distances), `manual` (reviewed mapping such as the zoning use-table), `estimated` / `fallback` (regional screening models only — never allowed in the decision layer).

**Rules carry their own provenance.** `constraint_rules` was the one evidence layer with no retrieved-at: every metric records when its source was read, while the rules deciding those metrics recorded only when the row was inserted. Loudoun's use table was named `2023-ord+2025-zoam`, listed `IP/GI/MR-HI` as by-right, and ZOAM-2024-0001 had removed exactly that in March 2025 — it claimed an amendment it did not reflect and decided 119 parcels for months. Each rule now records `reviewed_at` and `reviewed_against` (the named, dated instrument), and supersession is a column rather than the words "(supersedes X)" in a description. Each also records a `basis`, mirroring the `basis NOT NULL` that `cost_assumptions` has carried since Release 4 — the thresholds deciding PASS and FAIL had been the least-documented numbers in the engine while the costs derived from them were the best-documented. Most say *project judgement* outright, because that is what they are; the floodway threshold cites 44 CFR 60.3(d)(3) and the power statuses cite PJM's own codes. Three views follow: `v_rule_currency` reports a rule never checked as **never recorded** rather than assuming a default, `v_region_rule_drift` names any region still publishing verdicts decided under a superseded rule, and the worker warns about any rule whose params the gate never reads — nine such rows were found across three counties, looking authoritative and governing nothing. The engine cannot know an ordinance changed — nothing can, without watching the ordinance — but it can say how old its knowledge is.

**Atomic, versioned ingestion.** Each run stages every layer, records a **source snapshot** per layer (endpoint, record count, evidence class, fetched-at), and publishes in a single transaction via `promote_ingestion_run()` — cells/features are replaced region-scoped, parcels are upserted, and the previous run is superseded. A failed run is recorded as `failed` and publishes nothing.

**Zoning rules are data, not code.** Each jurisdiction's use table lives in `constraint_rules`, versioned and append-only, so a change in the law is a new row rather than a code edit — and the superseded row survives wherever a published run's verdicts still cite it. Loudoun's by-right list is now **empty**: ZOAM-2024-0001 moved `IP/GI/MR-HI` to special exception in March 2025, which is why every parcel there reads `CONDITIONAL` or better only on a parcel-specific approval. Where a county publishes no zoning at all, the absence is itself recorded — Texas counties hold no general zoning authority over unincorporated land (Local Government Code ch. 231), so Taylor parcels outside municipal limits read `CONDITIONAL` citing the statute, never `PASS`: an absence of prohibition is not a permission, and only the incorporated-places layer can tell the two apart.

## Monorepo Structure

- **[`client/`](./client/)** — Next.js 14 + TypeScript + Tailwind + Leaflet. Regional screening dashboard **and** the parcel qualification view: verdict-shaded cadastral parcels, gate ledgers with rationales and affected areas, metrics with evidence class + source organization, unresolved-diligence checklists. Vitest suite (`npm test`).
- **[`worker/`](./worker/)** — Python geospatial pipeline (geopandas, scikit-learn, turf-equivalent browser parity). `pipeline.py` runs the full staged→promote lifecycle; `loudoun_api.py` fetches county cadastral/regulatory layers; `overlay_layers.py` fetches the verification layers (TIGER roads, PAD-US, 3DEP slopes, utility territories, NWI wetlands with outage fallback); `power_evidence.py` fetches PJM RTEP upgrade records (resumable XML download) and queue activity; `parcel_gates.py` computes metrics and gate verdicts. Pytest suite (`python -m pytest -q`), run in CI ahead of any network work.
- **[`database/`](./database/)** — Supabase migrations + `tests/rls_tests.sql`, a repeatable allow/deny suite executed live as `anon` / `authenticated`.

## Data Sources

**Regional screening** layers degrade to a deterministic regional model when unreachable — the fallback is marked `fallback` in provenance and the UI shows the demo/PostGIS chip.

| Constraint | Live source | Stored metrics |
| :--- | :--- | :--- |
| Power proximity | HIFLD ArcGIS FeatureServers (lines ≥100 kV, named substations) | Interconnect / substation distances (mi), operator |
| Water availability | USGS NWIS (parameter 72019) | Water table depth, availability index |
| Seismic hazard | USGS ASCE 7-16 design service | Uniform-hazard PGA (g) |
| Flood/hurricane context | FEMA National Risk Index (counties) | County risk scores (context only) |
| Ambient cooling | NOAA ACIS GridData (PRISM normals) | CDD, mean temp, free-cooling hours |

**Parcel qualification** layers never fabricate values: an unreachable layer yields `UNKNOWN` gates with an explicit rationale. The verification stack is federal-first (Release 9): one federal adapter decides a gate in **any US county** — FEMA NFHL for floodway, PAD-US per-state geodatabases for protected land, NWI for wetlands, 3DEP for slope, TIGER for roads — with county mirrors winning when a county publishes a better local layer (Loudoun's FEMAFlood) and official-download fallbacks (download once → clip → cache per state) so an outage degrades to the same data the service would have served, not to `UNKNOWN`: FEMA flood (county mirror first, federal NFHL as the floor for every other county), NWI wetlands (official state geodatabase when the WIM REST service is down), and TIGER roads (cached clip, then the county's TIGER/Line shapefile when the Census WAF blocks the REST service).

| Gate | Source | Notes |
| :--- | :--- | :--- |
| Zoning DC-use | Loudoun County GIS — Zoning Ordinance districts | Dominant district per parcel overlay; rules from `constraint_rules` |
| Contiguous acreage | Loudoun County GIS — Land Records parcels | County PIN + legal acreage; GIS acreage from planar geometry |
| Floodway / floodplain | County FEMAFlood mirror (Loudoun); **federal FEMA NFHL REST service everywhere else** (Flood Hazard Zones layer 28) | The federal adapter is throttling-tolerant: geometry pages of 200 with retry/backoff, and a bbox whose query pages deep is spatially tiled until each tile pages shallowly; clips cached per state. Release 9 took floodway from 4,222 UNKNOWN (every parcel outside Loudoun) to 0 |
| Wetlands | USFWS NWI — live REST service, with the official state geodatabase as an outage fallback | Service-first; when WIM is down, the state GDB is downloaded once, clipped, cached (`worker/cache/`). Screening only; field delineation remains a diligence item |
| Protected land | USGS PAD-US 4.0 — **official per-state geodatabase, resolved from the ScienceBase State Downloads manifest** | The fetcher is state-parameterized (Release 9): it reads the release manifest at runtime, downloads the surveyed state's file once, clips, and caches per state. It reads the **combined inventory** (`PADUS4_0Comb_DOD_Trib_NGP_Fee_Desig_Ease` — fee + designation + easement), not the Fee-only layer, and it fixed two defects: Texas had been PASSing on a cached Virginia clip (wrong state's polygons), and the old Virginia clip itself was Fee-only |
| Slope | USGS 3DEP bare-earth DEM (`getSamples`) | Per-parcel elevation lattice → gradient-derived max/median slope % |
| Road access | Census TIGERweb — Transportation (S1100 primary, S1200 secondary), with per-state clip cache and the county TIGER/Line shapefile as fallback | Nearest suitable-road distance (mi). The Census WAF rate-blocks the REST service aggressively; a successful fetch is cached and an outage falls back to the cache, then to the canonical county shapefile on `www2.census.gov` |
| Water availability | Loudoun Water (LCSA) — public ArcGIS Service Area boundary (`gportal.loudounwater.org`, Boundary/MapServer/2, per-feature edit dates 2026) | The utility's own polygons: PASS when ≥50% of the parcel lies in a water-servicing area (ServiceType W/Both — the Central System covers Data Center Alley) whose record permits connections; CONDITIONAL on partial overlap (extension needed) or when the area record says additional connections are not permitted; FAIL when ≥50% lies in the utility's explicit **NOT Served by LW** boundary outside incorporated towns (no mapped public provider — on-site wells would be required); UNKNOWN inside incorporated towns (municipal providers not covered) or in unmapped gaps. Capacity, pressure, and connection fees are diligence items — the gate records availability, nothing more. Companion metrics from the same layer: **wastewater service** (ServiceType WW/Both) records the wastewater-servicing area and overlap share per parcel — informational only, never a gate. |
| Power capacity evidence | HIFLD Electric Retail Service Territories (utility, 2023) + PJM RTEP Project Construction Status (upgrades, dates) + PJM queue map + Loudoun legislative applications | Serving utility (observed); Board-approved area upgrades with approval + projected energization dates (observed/derived); queue activity within 3 mi; approved data-center applications overlapping the parcel (observed, with approval dates). **A MW figure is displayed only when a dated parcel-specific record states one** (Release 2.1): the curated `power_parcel_evidence` table quotes the utility statements from Board/Planning-Commission staff reports in the public LandMARC file of each approved county application — e.g. True North Data's documented ~60 MW connection (ZMAP-2017-0003, 2017-11-15 staff report), SDC Ashburn 1's Dominion-planned service (SPEX-2025-0031, 2026), the Rollins/AWS parcel's Poland Road substation capacity (SPEX-2019-0028, 2020), the Zebra East parcel's approved data-center + utility-substation proffer (ZCPA-2023-0005, 2025), and the Quarry Commerce Center parcel's documented underground electrical service (ZMAP-2017-0004, 2018). Every matched application was reviewed before curation — records without a utility-service statement (and the indefinitely-deferred Tuscarora Crossing substation) earn no evidence row. Zone-level forecasts (PJM 2026 Load Forecast: DOM-zone large-load 7,066 MW 2026 → 22,426 MW 2035) appear only as dated document facts. |

## Security Model (Release 0)

- **Anonymous API roles are read-only.** All write policies and write grants were revoked from `anon`/`authenticated`; ingestion requires the service role. Verified by `database/tests/rls_tests.sql` (all passing live).
- **`security_invoker` views throughout** — client views execute with the caller's RLS, so nothing is accidentally exposed through a view.
- **Staging tables are invisible to API roles** (401 over REST).
- The worker exits with an error if `SUPABASE_SERVICE_ROLE_KEY` is absent for a publishing run (dry-runs work without it).

## Survey Regions

Regions are keyed by county slug (`STATE-COUNTY`). The slug scopes publication: `promote_ingestion_run` swaps, uniqueness and supersession are region-keyed, so one state can host more than one diligenced county (OH-FRANKLIN and later OH-LICKING) without either touching the other. State-wide artefacts (PAD-US, NWI, TIGER, PJM RTEP) stay keyed by the state half of the slug.

| Region | County / Area | Grid operator | CLI |
| :--- | :--- | :--- | :--- |
| **Virginia (Loudoun)** — Data Center Alley *(parcel pilot)* | Loudoun County | PJM | `python pipeline.py --region VA-LOUDOUN` |
| **Texas (Abilene)** *(parcel pilot)* | Taylor County | ERCOT | `python pipeline.py --region TX-TAYLOR` |
| **Ohio (New Albany)** *(parcel pilot)* | Franklin County | PJM | `python pipeline.py --region OH-FRANKLIN` |
| **Ohio (Licking corridor)** *(parcel pilot)* | Licking County | PJM | `python pipeline.py --region OH-LICKING` |
| **Oregon (Boardman)** | Morrow County | BPA | `python pipeline.py --region OR-MORROW` |

Ad-hoc surveys: `--region <slug> --bbox min_lon,min_lat,max_lon,max_lat --county <label>`. A legacy bare state code (`--region VA`) still maps to that state's one preset; it cannot name a new region — a second county in a state needs its own slug and preset.

## Quick Start

### 1. Database (Supabase / PostGIS)

```bash
supabase db push        # applies database/migrations/ in order
psql "$DB_URL" -f database/tests/rls_tests.sql   # optional: run the RLS suite
```

Key migrations: provenance schema (`data_sources`, `ingestion_runs`, `source_snapshots`), parcel tables (`land_parcels`, `parcel_metric_values`, `parcel_gate_results`), staging + `promote_ingestion_run()` RPC, client views (`v_land_parcels_map`, `v_parcel_gates`, `v_parcel_metrics`), and the security lockdown.

### 2. Worker

```bash
cd worker && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # set SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY

python pipeline.py --region VA-LOUDOUN --dry-run   # fetch + compute, publish nothing
python pipeline.py --region VA-LOUDOUN             # staged, atomically promoted
```

Publishing requires `SUPABASE_SERVICE_ROLE_KEY` (the anon key can no longer write, by design).

### 3. Client

```bash
cd client && npm install
npm test        # vitest: null-safety + prime-zone semantics
npm run dev     # http://localhost:3000
```

### Tests

```bash
cd worker && pip install -r requirements-dev.txt
python -m pytest -q   # 264 tests, offline: no network, no database

cd client && npm test # 43 tests
```

The worker suite is regression-shaped: it pins the defects this pipeline has
actually shipped — NaN reaching the JSON encoder (three separate times),
Python/Postgres rounding disagreements, Franklin County's mixed acre and
square-foot legal areas — plus the overlay geometry and slope-cache
provenance rules that gate verdicts depend on. `test_underwriting.py` covers the
cost model in three dimensions — the arithmetic, the provenance every
estimated metric must carry, and the refusals (an unsampled slope prices at
nothing rather than at a confident area-only figure). `test_qualify_parcels.py`
runs the whole gate engine over a synthetic county built so that each
parcel's correct verdict is known by construction (40% wetland, 30% slope,
residential zoning), rather than recorded from a previous run — a recorded
fixture pins whatever the code did that day, including its bugs. It runs in CI before any
network fetch, so a change that would compute wrong verdicts fails in
seconds rather than after a 13-minute publish.

Environment: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (in `.env.local` locally, per-environment on Vercel).
